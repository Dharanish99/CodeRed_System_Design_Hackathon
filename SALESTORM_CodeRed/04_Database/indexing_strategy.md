# Index and retention strategy
Inventory PK inventory_id; unique(sale_id,product_id) routes one allocation. Reserve update hits one PK, no table scan. Partial reservation index(expires_at) WHERE status='RESERVED' feeds sweeper; unique active purchase(customer_id,sale_id) prevents new-key abuse for the same sale. Unique request(customer_id,operation,idempotency_key) plus request hash protects repeated commands.
Payment UNIQUE(reservation_id), UNIQUE(provider,provider_ref), provider idempotency key unique; partial unresolved timestamp index supports reconciliation. Order UNIQUE(reservation_id), customer_id/created_at supports history. Outbox unpublished(created_at) and inbox PK(consumer,event_id). Shipment UNIQUE(order_id) for the single-shipment baseline. Notification unique(event_id,channel).
Partition high-volume audit/outbox history by month; archive published outbox only after consumer retention/reconciliation safety interval. Do not purge payment/order identity tombstones while replay/refund is possible. Event retention proposed 7d, DLQ 30d, audit per business retention policy; replay older than retained inbox requires business-key guards. Add indexes only after query-plan/load evidence; extra indexes increase hot-write cost. Audit table growth and vacuum lag are monitored.
