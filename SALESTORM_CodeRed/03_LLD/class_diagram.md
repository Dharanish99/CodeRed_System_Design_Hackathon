# Class contracts
Three critical modules: Inventory, Payment and Order. The class diagram shows domain-facing interfaces, not generated application code. ReservationService owns guarded transitions, PaymentService intent/reconciliation semantics, and OrderService audit/lifecycle. Repositories participate in a single owner-local UnitOfWork; no individual repository commits independently. DTO validation/auth belongs in controllers; state/hash validation belongs in domain services; driver/provider exception normalization belongs in adapters. Retry belongs at transaction/command boundary, never around isolated UPDATE only.
PaymentGateway must distinguish PENDING/UNKNOWN from definitive failure, support same-intent lookup and terminal cancellation. New adapters require contract tests; unsupported contracts cannot be hidden behind an interface. Payment and Inventory inbox effects invoke service methods in the same UnitOfWork as inbox insertion. Local observer callbacks cannot replace durable broker delivery.
